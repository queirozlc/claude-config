# New idea validation

Use for an explicit request to evaluate an idea before meaningful user evidence exists. These are advisory questions. Select the ones relevant to the decision; do not force a fixed interview or block implementation.

1. Diagnosis: state the problem, proposed customer, current alternative, and the assumption with the greatest effect on viability.
2. Evidence: distinguish observed past behavior and costly commitments from stated intent. Use [customer interviews](../references/mom-test.md) to ask about specific past problems and their cost.
3. Customer segment: identify who has the problem, how urgently, and how to reach them. Use [positioning](../references/obviously-awesome.md) when the segment or alternative is unclear.
4. Market: estimate reachable customers and existing spending with named sources. Use ranges when evidence is uncertain. Do not manufacture market size.
5. Distribution: identify a plausible channel and the constraint it must overcome. The growth engine discussion in [Lean Startup](../references/lean-startup.md) is a hypothesis to test, not a guarantee.
6. Experiment: select the cheapest test that could change the decision. Use the [experiment reference](../references/testing-business-ideas.md). State the hypothesis, observable result, proposed threshold, cost, and duration where supported.

Report what is supported, what remains uncertain, and the next useful test. A failed evidence check changes the recommendation; it does not override the user's request. Continue with conditional advice when data is absent. Respect a later instruction to implement and carry forward material assumptions.
